# Polymarket Canonical Merge Plan

> For Hermes: this repo is now the canonical runtime base. Use the subagent-driven-development skill for follow-on implementation tasks.

Goal: unify the useful pieces of the local Polymarket bot portfolio into one working project today, without creating a Frankenstein codebase.

Architecture: keep `polymarket-5min-bot` as the runtime spine, selectively absorb high-leverage ideas from the other repos, and keep the Karpathy-style autoresearch loop generic so it can later be reused outside Polymarket. Runtime code stays in the canonical repo; heavyweight experiments and alternate architectures remain source references, not merge targets.

Tech stack: Python, Click CLI, YAML config, unittest, pandas backtesting, generic research-loop adapters.

---

## Canonical-base decision

Chosen canonical repo: `/root/git-repos/polymarket-5min-bot`

Why this wins:
- has a real CLI already
- has offline backtest path
- has paper/live scaffolding
- has a sample dataset
- has the best test coverage among the Python Polymarket repos that matter for today
- already accepts selective imports cleanly

Why the others are not the base:
- `polymarket-bot-swarm`: good filter ideas and broader scan heuristics, but more sprawling and less test-centered
- `poly-edgefinder`: useful research/exploration concepts, but not the best runtime spine
- `polymarket-bot-arena`: interesting dashboard/feedback ideas, but not a day-one execution base
- `polymarket-botkit`: valuable Rust architecture inspiration, not a fast Python merge target
- `polymarket-alpha-v2` / `polymarket-trading-system`: smaller side experiments, not the strongest canonical core
